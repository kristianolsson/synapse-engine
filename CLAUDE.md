# synapse-engine

Ingestion/dispatch service bridging Email + Telegram with a pluggable AI
provider (Claude Code CLI / Antigravity CLI / Gemini CLI (deprecated)) acting
on a git-backed vault of notes/protocols. See `README.md` for setup and
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for how the pieces fit
together — read that before making non-trivial changes here.

## Hard rules

Each of these caused a real bug once. Don't reintroduce them.

- **Never construct `SessionManager()` or `RateLimiter()` outside `main.py`.**
  Both are meant to be built once and passed as constructor params into
  `EmailListener`, `TelegramListener`, and `ReminderScheduler`. A fresh
  instance silently loses in-memory state — `SessionManager`'s per-user
  `/stats` preference isn't persisted to disk, so a fresh instance always
  falls back to the config default regardless of what the user actually set.
  If you need one of these, accept it as a parameter from whoever constructed
  you.
- **Every prompt sent to `pipe_to_provider()` must be built via
  `build_prompt(IncomingMessage(...))`**, never a bare string. An unwrapped
  internal instruction (a retry, a nudge, anything generated by this codebase
  rather than typed by a user) arrives mid-session looking like an
  unattributed injected instruction and gets treated as a prompt-injection
  attempt — this has happened in production.
- **Any `git` command against `VAULT_PATH` or `REMINDERS_JSON_PATH` must hold
  `GLOBAL_PROVIDER_LOCK`** (`providers/base.py`). The AI provider's own shell
  tool can run git against the same vault concurrently; skipping the lock has
  corrupted `FETCH_HEAD` before.
- **New Telegram-outbound code calls `channels/telegram/reply_dispatch.py`'s
  `safe_reply_text()`/`build_reply_keyboard()`**, not `message.reply_text()`
  or `send_telegram_message()` directly. Telegram silently rejects a whole
  message on malformed HTML/Markdown; `safe_reply_text` is the one place that
  retries as plain text instead of losing the reply outright.
- **Email stats formatting is centralized — Telegram's isn't (yet).**
  `send_reply(..., stats=some_dict_or_None)` (`channels/email/reply.py`)
  formats and appends the stats footer internally; always pass the raw dict
  through, never pre-format it. `send_telegram_message()` has no equivalent
  `stats` kwarg, so every Telegram call site currently does
  `if session_manager.get_stats_enabled(key): text += format_stats_telegram(stats)`
  manually before sending — match that pattern for now rather than inventing
  a different one.

## Conventions

- **New tool CLI in `tools/`**: JSON output via shared `_out()`/`_err(message,
  code)` helpers with a documented error-code taxonomy, `sys.path.insert(0,
  ...)` bootstrap, and path resolution through `services.ingestion.config`
  constants — never recompute `VAULT_PATH`/`CALENDAR_*_PATH` locally. Follow
  `etrade_cli.py`/`reminder_cli.py`/`options_bot_cli.py`/`amazon_fresh_cli.py`'s
  shape, not `gmail_cli.py`/`calendar_cli.py`'s older plain-text convention.
- **Tests** live under `services/ingestion/tests/<module>/`, mirroring the
  source tree (`tests/channels/`, `tests/core/`, `tests/tools/`,
  `tests/utils/`). Don't add a new top-level test location.
- **Same-package imports** use the minimal relative depth for where a file
  actually lives (a file in `core/` imports siblings as `from .pipe import
  ...`, not `from ..core.pipe import ...`).
- Touching E*TRADE auth or the retry-after-auth mechanism? Read
  [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#the-etrade-pin-auth-fallback-and-retry-mechanism)
  first — the `SYNAPSE_*` env-var correlation mechanism spans four files and
  is easy to half-implement.

## Running things

```bash
python -m pytest services/ -v         # full test suite — no CI runs this for you
python -m services.ingestion.main     # run the service directly (needs .env)
```

## Where things live

| Changing... | Look at |
|---|---|
| How a message reaches the AI and back | `core/pipe.py` (`build_prompt`, `pipe_to_provider`), `providers/` |
| Per-user state (sessions, `/stats` prefs) | `core/session_manager.py` — see the hard rule above |
| Scheduled/recurring reminders | `core/scheduler.py` + `tools/reminder_cli.py` (two independent writers to `reminders.json`, coordinated via a `.lock` file) |
| Telegram bot behavior | `channels/telegram/listener.py` — large file; command handling, E*TRADE PIN interception, Actionable Forms, and message dispatch all live in it |
| Email behavior | `channels/email/listener.py` + `reply.py` |
| E*TRADE / options-bot | `tools/etrade_cli.py`, `tools/stocks/`, `tools/options_bot_cli.py` |
| Gmail / Calendar | `tools/gmail_cli.py`, `tools/calendar_cli.py` — share OAuth conceptually (`get_credentials()`) though it's duplicated rather than actually shared today |
